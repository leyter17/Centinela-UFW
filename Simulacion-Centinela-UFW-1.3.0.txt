 3. SIMULACIÓN A — REGRESIÓN DEL BUG «YOU NEED TO BE ROOT»
────────────────────────────────────────────────────────────────────────

Objetivo: reproducir EXACTAMENTE el escenario del informe del usuario
(v1.2.0: dos ERROR en el registro y en el informe a las 00:02:39 y
00:02:45 aunque la contraseña fuera correcta) y comprobar que en la
v1.3.0 no aparece ningún error.

Escenario: la app arranca como usuario normal (uid 1001) con un ufw
simulado que exige root para las consultas y un pkexec simulado que
autentica correctamente.

Fragmento del informe automático generado por la app (informe.log):

  2026-11-21 09:47:42  INFO   [inicio] Sesión iniciada — Centinela UFW v1.3.0
                                 · usuario: z (uid 1001)
  2026-11-21 09:47:42  CMD    [ufw] $ ufw status verbose
  2026-11-21 09:47:42  DETAL  [ufw] código de salida: 1
          stdout:
          stderr: ERROR: You need to be root to run this script
  2026-11-21 09:47:42  DETAL  [ufw] La consulta sin privilegios requiere root
                                 (respuesta esperada de ufw, no es un error);
                                 se escala mediante pkexec
  2026-11-21 09:47:42  INFO   [ufw] UFW exige privilegios de root incluso para
                                 consultar el estado (comportamiento normal de
                                 ufw, no es un error): las consultas se
                                 realizarán mediante pkexec
  2026-11-21 09:47:42  CMD    [ufw] $ pkexec ufw status verbose
  2026-11-21 09:47:42  DETAL  [ufw] código de salida: 0 · stdout: Status: inactive
  2026-11-21 09:47:42  CMD    [ufw] $ pkexec ufw status numbered
  2026-11-21 09:47:42  DETAL  [ufw] código de salida: 0
  2026-11-21 09:47:42  OK     [ufw] Estado refrescado: inactivo · reglas: 0
                                 · logging: on (low)
  2026-11-21 09:47:42  OK     [app] Estado del firewall actualizado. · 0 reglas

Comprobaciones:
  OK  · Cero entradas de nivel ERROR relacionadas con la consulta sin root
        (en v1.2.0 eran dos ERROR: una por cada consulta de estado).
  OK  · Cero entradas ERROR en todo el informe de la sesión.
  OK  · El estado del firewall se cargó correctamente vía pkexec
        (la «contraseña correcta» funciona y deja el estado refrescado).
  OK  · El registro de actividad de la app no muestra ningún error.
  OK  · Captura de pantalla del Panel: firewall INACTIVO cargado, sin errores.

Resultado: SIMULACIÓN A — CORRECTA (bug de v1.2.0 corregido y verificado).

 5. SIMULACIÓN C — FLUJO FUNCIONAL COMPLETO (--simflow, 16 PASOS)
────────────────────────────────────────────────────────────────────────

Objetivo: validar de principio a fin el funcionamiento real de la app
contra un ufw simulado con estado, ejecutando como root (rama de
ejecución directa del motor, sin pkexec).

Pasos ejecutados:  1 activar firewall · 2-4 añadir reglas (22/tcp SSH,
80,443/tcp Web) · 5 perfil Oficina (políticas + red local + SSH
limitado) · 6 logging bajo · 7 borrado INTENCIONAL de la regla inexistente
9 (error real) · 8 exportación COMPLETA · 9-10 cambio a «solo errores» y
exportación · 11 volver a «completo» · 12 NUEVO: borrar el registro
automático · 13 borrado real de la regla 2 · 14 modo simulación (regla
8080 sin ejecutar) · 15 guardar ajustes · 16 salir.

Comprobaciones (13/13 CORRECTAS):
  OK  · Flujo completo ejecutado y salida limpia (código de salida 0).
  OK  · El firewall quedó ACTIVO tras el paso 1.
  OK  · El error intencional quedó registrado con detalle completo
        (comando, código de salida y «ERROR: Could not find rule with
        number 9») y aparece en la exportación completa (251 líneas).
  OK  · La exportación COMPLETA se creó correctamente.
  OK  · La exportación SOLO ERRORES se creó (9 líneas) y contiene
        únicamente el error: ninguna línea CMD/INFO/AVISO.
  OK  · El registro automático se borró en el paso 12 (NUEVO 1.3.0):
        informe.log quedó sin el historial anterior.
  OK  · Tras el borrado, el registro sigue activo: el borrado de la
        regla 2 (paso 13) y el modo simulación (paso 14) quedaron
        grabados en el fichero recreado (92 eventos nuevos).
  OK  · El modo simulación mostró el comando y NO lo ejecutó
        (la regla 8080 nunca entró en el firewall).
  OK  · Estado final coherente: active=1, logging=on (low),
        políticas deny/allow/deny, 7 reglas con sus gemelas (v6).
  OK  · 5 capturas de pantalla documentan Reglas, Perfiles, Avanzado,
        Informe (con el nuevo botón «Borrar registro automático») y
        Acerca de.

Resultado: SIMULACIÓN C — CORRECTA (13/13).
